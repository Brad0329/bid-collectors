# 누적 부채 점검 (주기 실행 — 목록만 만들고, 결정은 사용자가)

부채는 우연히 발견돼 왔다 — 문서에 적힌 함정을 코드 두 곳 중 한 곳만 고쳐 재발했고(반복
실수), 같은 deny 출력 코드 복사본 4벌이 같은 버그를 4번 가졌고(중복 로직), 지침 문서가
88KB까지 자라며 같은 사실이 여러 곳에서 서로 어긋났다(복수 원본). 전부 **누가 우연히
밟아서** 드러났다. 이 스킬은 그것을 **주기적으로, 체계적으로** 찾는다.

## 언제 부르는가

- **Phase 3~5개마다.** 메인 agent는 그 시점이 되면 사용자에게 알리고, 실행은 사용자가 부른다.
- **사용자 호출 전용이다.** 그리고 **이 스킬은 아무것도 고치지 않는다** — 산출물은 목록뿐이다.

## 절차

### 1. 스캔 3종 — 서브에이전트 병렬로 (메인은 결론만 받는다)

가능하면 `Explore`·`general-purpose`를 병렬로 띄운다. 못 쓰면 메인이 직접 하되,
검색 덤프를 컨텍스트에 담지 말고 발견 항목만 남긴다.

| 스캔 | 어디서 찾나 | 무엇이 걸리나 |
|---|---|---|
| **반복 실수 유형** | Phase 로그의 "실패한 접근", 플레이북, git log | 같은 부류의 실수가 **2회 이상**. 특히 **문서에 적혔는데 또 밟은 것** — 구조(훅·테스트) 강제 1순위 후보 |
| **중복 로직** | 코드 | 같은 판정·규칙·상수·매직값이 2곳 이상인데 **대조 테스트가 없는 것**, 복사된 코드 블록, 버그를 한 층만 고친 흔적 |
| **한 사실의 복수 원본** | 문서 ↔ 문서, 문서 ↔ 코드 | 같은 사실이 여러 곳에 병기된 것 — **이미 서로 어긋난 것 최우선**(어긋남이 곧 증거다). CLAUDE.md 규칙 개수 상한 점검(`python scripts/count_claude_rules.py`)도 여기서 함께 |

### 2. 목록 형식 — 근거 없는 항목은 올리지 않는다

항목마다 한 줄씩: **유형 / 위치(파일:줄 또는 문서 절) / 근거(횟수·어긋난 내용) / 처방 후보
한 줄 / 예상 트랙(저위험·일반)**. "냄새가 난다"는 근거가 아니다 — 횟수와 위치가 근거다.

- **발견 0건이어도 보고한다** — 무엇을 훑었는지(로그 N개·파일 N개)와 함께. 조용한 빈 보고는
  "안 훑었다"와 구분되지 않는다.
- 항목이 많으면 **구조 강제 가능한 것부터** 정렬한다(훅·테스트로 막을 수 있는 반복 실수 >
  대조 테스트를 붙일 중복 로직 > 이관·링크화할 복수 원본).

### 3. 사용자가 결정한다

목록을 보고 사용자가 고른다 — ① **정리 Phase로 간다**(번호를 받아 계획에 넣는다)
② **곁가지 몇 개만**(5분 규칙 — 항목별 커밋 분리) ③ **안 한다**(근거와 함께 기록).
결정은 `work_log/plan.md`에 상태 어휘로 남긴다 — 목록만 만들고 결정을 안 남기면
다음 audit이 같은 목록을 다시 만든다.

### 4. 정리 Phase로 가게 되면

- **항목별로 커밋을 나눈다.** 정리 커밋에 기능 변경을 섞지 않는다.
- **기계적 이동·분리는 공개 표면을 유지해 테스트를 한 줄도 안 고치는 방식으로**
  (`노하우_프로세스.md`) — 테스트 통과가 "동작 불변"의 증명이 된다.
- **반복 실수는 문서 보강이 아니라 구조 강제로 푼다** — 문서에 적혔는데 또 밟은 것이
  목록에 있다는 것 자체가 문서로는 안 막힌다는 증거다.
- 이관·삭제 전에 원본이 갈 곳에 실제로 존재하는지 확인한다(지우는 게 아니라 옮긴다).
