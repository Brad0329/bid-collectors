## 1. 무엇이 바뀌었나
- 버전 · 커밋 · Phase: **1.3.0** · Phase 007 커밋(이 문서와 같은 커밋) · plan.md Phase 007. 요청서: bidwatch `docs/requests/bid-collectors_alio_fetch_detail.md`
- **계약**: 시그니처·`Notice`·`CollectResult`·`bid_no`·공개 export는 그대로다. `AlioCollector.fetch_detail`이 None 대신 dict를 돌려주는 기능이 추가됐다 → minor
  (`docs/CONTRACT.md` 변경 이력 2026-09-25 v1.3.0 행, 사용자 확정: 실패 = 예외 · `bFiles` 포함).
- **동작** — `await AlioCollector().fetch_detail("ALIO-{seq}")`:
  - `GET https://alio.go.kr/occasional/findBidDtl.json?seq={seq}`를 1회 부른다(인증 없음). **`collect()`는 부르지 않는다.**
  - 반환 dict:
    - `attachments`: `[{"name": fileNm, "url": fileNo}, …]`(`fileList` 순서 그대로). 첨부가 없으면 `[]`이고 None이 아니다.
    - `content`: `bidDtl.content`에서 HTML을 걷어낸 것. 없으면 `""`.
    - 그 밖의 키: `data.bidDtl`에서 비어 있지 않은 필드 전부를 원래 이름 그대로 담는다. 0은 포함하고 None·빈 문자열·공백만 있는 값은 뺀다.
      예: `refrUrl`·`bidType`·`apbaId`·`ingStatus`·`totContAmt`·`disclosureNo`·`submissionNo`·`idate`·`bFiles`…
      목록 extra와 겹치는 `seq`·`rtitle`·`pname`·`bdate`·`bidInfoEndDt`도 들어 있다.
  - **실패는 예외다. None을 돌려주지 않는다.** 알리오는 없는 seq에도 HTTP 200 + `status:"error"` "시스템 에러입니다. 관리자에게 문의하세요."를 주므로, 없는 번호와 장애가 구분되지 않는다.
    - HTTP 오류 → `httpx.HTTPStatusError`
    - `status != success`·`bidDtl` 없음·`fileList`가 list가 아님 → `ValueError`(메시지에 status·message)
    - `ALIO-{seq}` 형식이 아닌 bid_no → 요청 없이 `ValueError`
  - 실측(2026-09-25):
    - 목록 1~3페이지 30건: 키 집합과 첨부 건수가 30/30 일치했고 예외는 0건이었다. 첨부는 합계 83개였다.
    - **`refrUrl` 30건 중 g2b 20건 · onbid.co.kr 10건** — 요청서 표본(나라장터 13·한전 SRM·수자원·LH·한수원 6)과 달리 **온비드도 온다.**
    - `content`가 비어 있지 않은 공고는 0건이었다.
    - 고장 시나리오 5건(없는 seq 3·형식 2)은 전부 예외였다.
- **`docs/interface.md` diff**:
  - §2 `BaseCollector.fetch_detail` docstring: K-Startup(실패 None)과 알리오(v1.3.0, 실패 예외, 반환 dict 모양)로 나눠 적었다.
    나머지 수집기는 None이고, collect 중에는 부르지 않는다.
  - export 표의 `AlioCollector` 행 비고에 "`fetch_detail` 첨부·원문 링크 (v1.3.0)"를 더했다.
  - 끝머리의 "`v1.2.5` 기준"을 "`v1.3.0` 기준"으로 바꿨다.
  - 이 저장소의 `docs/interface.md`를 bidwatch 쪽에 그대로 복사하면 된다(v1.2.5 반영 이후 바뀐 곳은 위 세 곳뿐이다).

## 3. 검증 방법
- `pip install -e C:\Users\user\Documents\bid-collectors`를 다시 실행해야 한다. editable이라 코드는 이미 1.3.0이지만 메타데이터(`pip show`)는 1.2.5로 남아 있다.
- `backend/.venv/Scripts/python.exe -m pytest backend/tests` — 2026-09-25 이 코드로 실행해 **126 passed**를 확인했다. 기대값이 바뀌는 테스트는 없다.
- 실테스트:
  1. 알리오 공고 팝업을 연다.
  2. 첨부 목록이 뜨는지 본다(표본 30건 중 29건 이상 첨부 있음).
  3. 원문 링크 버튼을 확인한다(g2b·onbid 도메인).
  4. 나라장터 번호가 있으면 연결 공고가 보이는지 확인한다.
  5. 같은 팝업을 다시 열 때 상세 호출이 나가지 않는지 확인한다(#3·#4).
  6. 없는 seq(예: DB 행의 bid_no를 `ALIO-999999999`로 바꿔 부르기)에서 경고 로그가 남고 팝업이 깨지지 않는지 확인한다.
