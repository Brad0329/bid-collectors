## 1. 원칙: 허용의 기준은 "위험" (2026-08-22 사용자 결정, CLAUDE.md 불변 규칙)

- **트레이드오프**: "승인한 것만 돌았다"는 보장 대신 git 이력·작업 로그가 그 역할을 한다.

## 3. 허용 규칙 작성법

1. **규칙을 추측하지 않는다.** 사용자가 "다시 묻지 않기"를 한 번 고르게 한다 — 매칭하는 그
   코드가 `settings.local.json`에 정확한 패턴을 적는다 `[H3]`.
2. **효력이 있는 것은 `settings.local.json`뿐이다.** `settings.json`의 `allow`는 이 환경에서
   안 걸린다(`hooks`·`env`·`deny`는 산다 — deny는 파괴적 명령을 던져야 시험되므로 확인하지
   않았고 지우지도 않는다) `[H6]`. local은 gitignore라 공유 불가 — 새 클론은 §5 스타터로
   시작한다. 그래서 템플릿 `settings.json`의 allow는 비어 있다.
3. **규칙 문법**:
   - 와일드카드는 작동한다. **패턴에 역슬래시가 있으면 죽는다** — 경로는 슬래시로 부르고
     슬래시로 등록한다 `[H6]`.
   - `X*`(공백 없이)는 `X`와 `X <인자>`를 함께 받는다 `[H10]`.
   - **`X:*`(콜론+별표)는 `X *`와 동등하다** — 공식 문법이고 패턴 끝에서만 와일드카드다(가운데 콜론은
     리터럴). 승인 창은 공백 형태를 적지만 손으로 쓴 규칙·다른 프로젝트에서 온 규칙은 이 형태가 흔하다.
     분석기가 이걸 몰라 거짓 보고서를 낸 실사례 `[H15]`. 출처: code.claude.com/docs/en/permissions.
   - `Bash(...)`와 `PowerShell(...)`은 별개다 — **양쪽에 넣는다** `[H1]`.
   - 한글(비ASCII)이 든 명령을 "다시 묻지 않기"로 열지 않는다 — 파일명이 깨져 적힌다
     `[H9]`. 열어야 하면 ASCII 경로로 부른다. (단 `git add *`처럼 와일드카드 규칙이 있으면
     한글 인자도 걸린다 `[H12]`.)
   - 자동 승인이 위험한 명령은 인자를 필수로 건다(`dart format *` — 맨몸 전체 포맷은 묻는다).
   - `deny`가 `allow`보다 우선한다. deny도 셸 도구별로.
4. **일회성 명령을 열지 않는다** — 다시 부를 일이 없어 이득 0, 권한만 남는다 `[H9]` `[H11]`.
   세션 UUID·스크래치패드 절대경로·인라인 파이썬이 박힌 규칙이 전형이다. 호출 형태로 푼다(§4).
5. **규칙이 걸리는지 검증할 때 읽기 전용 명령을 쓰지 않는다.** `git status`·`git log`류는
   규칙과 무관하게 자동 허용처럼 동작해 어떤 규칙을 넣어도 "걸렸다"가 나온다 `[H5]`.
   **실제로 묻던 명령으로 검증한다.** ⚠️ 단 "자동 허용 부류"를 단정하지 말 것 — 자동 허용으로
   보였던 `Set-Location`이 다른 환경·시점에선 9건을 물었다 `[H14]`. **물면 규칙을 넣는다.**
6. **규칙은 즉시 걸린다 — 재시작을 기다리지 않는다** `[H14]` (local에 넣자마자 같은 세션의
   다음 보고서에서 사라짐. [H4]·[H5]의 "미적용"·"갈렸다" 오진은 죽은 settings.json에 넣었거나
   벽시계로 판정한 것이 원인). 그 자리에서 실제로 묻던 명령으로 재검증하고, 판정은 §2 판정법.
7. **audit 때 local을 청소한다 — 넓히는 게 아니라 줄이는 작업이다** `[H14]`. 지난 세션의
   스크래치패드 경로, 다른 저장소 경로, 깨진 한글, 훅이 막는 형태의 규칙은 죽은 규칙이다
   (실사례: 169개 → 64개).
8. **규칙을 닫을 때는 두 파일을 함께 본다** — local에 같은 규칙이 있으면 그쪽이 계속 연다 `[H6]`.

## 4. 호출 형태 — 한 호출 = 한 명령, 앞에 무엇도 붙이지 않는다

| 피할 형태 | 왜 | 대신 |
|---|---|---|
| `cd X && cmd` / `Set-Location X; cmd` | 접두사 규칙에 안 걸리거나(Bash), 앞머리 하나로 뒤까지 통째로 통과해 승인 이력을 못 믿게 된다(PowerShell) `[H1]` `[H7]` | `cd` 따로, 명령 따로. cwd는 호출 사이에 유지된다 |
| `FOO=bar cmd` / `$p = "…"; cmd` | 리터럴로 시작하지 않아 allow 규칙에 안 걸린다 `[H1]`. 공식 문서: **알려진 안전 변수**(`NODE_ENV` 등) 대입만 매칭 전에 벗겨지고 그 외 변수는 안 걸린다(deny는 어떤 대입도 넘어 매칭) `[H15]` | `settings.json`의 `env` |
| `& (Join-Path …)` 식 표현식 시작 | 같은 이유(77.8초) `[H6]` | 전체 경로를 글자 그대로, 그 리터럴로 규칙 등록 |
| `& "<경로>"` (호출 연산자+따옴표) | 규칙은 맨몸을 전제 — 같은 adb devices가 27.6초 vs 2.2초 `[H14]` | 경로에 공백이 없으면 `&` 없이 맨몸으로 |
| **쓰는** `git -C <경로>` (add·commit) | 규칙이 `git add *` 형태를 전제(21건 147초) `[H6]` `[H14]` | 루트에서 맨몸으로. **읽는** git(status·log·diff·show)의 `-C`는 규칙을 넣어 열 수 있다 — cwd 드리프트 확인용(`[H13]`) |
| `A; if ($?) { B }` 복합문 | 어느 규칙에도 안 걸린다(4건) `[H14]` — [H7]의 "앞머리 통과"와 갈리는 관측: 하네스 동작이 바뀌었을 수 있다. 어느 쪽이든 처방 동일 | 두 번에 나눠 부른다 |
| 공백 없는 경로를 따옴표로 | `git commit -F "경로"`가 `-F *`에 안 걸림(18.5초) `[H6]` | 따옴표 없이 |
| `cmd \| Select-String` / `2>&1` | PowerShell에선 꼬리가 검사되지 않고, 자르려다 3~7배 `[H7]` `[H8]` | 그냥 받는다 — 큰 출력은 하네스가 파일로 떨궈 준다 |
| `python -c "…"` | 이스케이프째 박제되는 죽은 규칙 `[H11]` | 스크립트 파일 |
| 스크래치패드 절대경로 (훅 `no_scratchpad_path`가 막는다) | 세션 UUID가 박혀 다음 세션에 안 걸린다 `[H11]` | 파일은 Read/Write 도구로, 스크립트는 `scripts/`에 두고 경로는 스크립트 안에서 계산 |
| 셸에서 환경변수 확인 | 일회성(82.3초) `[H11]` | 스크립트 안에서 `os.environ` |
| 셸 `for/do/done` | 규칙에 안 걸린다 | 파이썬 |

- **★ 앞머리 통과를 우회 수단으로 쓰지 않는다.** 허용된 명령을 앞에 붙여 뒤엣것을 통과시키면
  사용자는 자기가 승인한 것만 돌았다고 오해한다. 명령은 있는 그대로 부르고, 물으면 물리는
  대로 둔다. 속도보다 이쪽이 우선이다 `[H7]`.
- **작업 디렉토리**: 트리 안 `cd`는 유지되고, 트리 밖은 거부·루트로 리셋된다 `[H5]`. 유지되기
  때문에 **드리프트** 위험이 있다 — 하위에서 루트용 명령을 부르면 에러 없이 조용히 다른 일을
  한다(`pytest tests/` 0건 통과, `git add -A` 하위만). 하위에 들어갔으면 끝나자마자 돌아온다.
  100% 믿지도 않는다 — 중간에 초기화된 실측이 있다. "찾을 수 없다"류로 죽으면 cwd부터 본다.
  **Bash·PowerShell 도구는 cwd를 공유하고, 승인된 추가 디렉토리로의 `cd`는 트리 밖이어도
  유지된다** `[H13]` — 다른 저장소에서 작업한 뒤 `git add -A`를 부르면 그쪽이 담긴다.
  다른 저장소에 들어갔으면 **돌아오기 전에 `git status`로 어느 저장소인지 본다.**
- **여러 줄 커밋 메시지**: here-string·인라인으로 넘기지 않는다(`pathspec` 오류). 저장소 루트
  `.commit_msg.txt`(gitignore)에 쓰고 `git commit -F .commit_msg.txt`. 경로를 고정해야 규칙
  한 줄로 영구히 끝난다. `.git/` 안에 두지 않는다(보호 디렉토리, 137초) `[H8]`.

## 5. settings.local.json 스타터

hanmunstudy(Flutter·Windows) 실물(2026-08-22) 기준이다. 초기화 때 `.claude/settings.local.json`에
붙여 넣고(없으면 만든다), **이 스택에 없는 줄은 뺀다.** 전역 `python` 기준 — 가상환경이면
`.venv/Scripts/python.exe`처럼 슬래시 경로로 바꾼다. `additionalDirectories`의 프로젝트 폴더명은
`~/.claude/projects/` 아래 실제 이름으로(경로의 `:`·`\`가 `-`로 바뀐 형태).

```json
{
  "permissions": {
    "allow": [
      "WebSearch",
      "WebFetch",
      "Write(.commit_msg.txt)",
      "Edit(.commit_msg.txt)",
      "PowerShell(git add *)",
      "PowerShell(git commit -F .commit_msg.txt*)",
      "PowerShell(Set-Location *)",
      "Bash(git add *)",
      "Bash(git commit -F .commit_msg.txt*)",
      "Bash(cd *)",
      "PowerShell(flutter test)",
      "PowerShell(flutter test --reporter failures-only)",
      "PowerShell(flutter analyze)",
      "PowerShell(flutter doctor)",
      "PowerShell(flutter devices)",
      "PowerShell(flutter pub get)",
      "PowerShell(flutter pub outdated)",
      "PowerShell(flutter clean)",
      "PowerShell(flutter build apk*)",
      "PowerShell(dart analyze)",
      "PowerShell(dart format *)",
      "PowerShell(python -m pytest *)",
      "PowerShell(python scripts/*)",
      "Bash(python -m pytest *)",
      "Bash(python scripts/*)",
      "PowerShell(C:/Users/user/AppData/Local/Android/Sdk/platform-tools/adb.exe devices)",
      "PowerShell(C:/Users/user/AppData/Local/Android/Sdk/platform-tools/adb.exe install -r *)",
      "PowerShell(C:/Users/user/AppData/Local/Android/Sdk/platform-tools/adb.exe logcat *)"
    ],
    "additionalDirectories": [
      "C:/Users/user/.claude/projects/C--Users-user-Documents-<프로젝트폴더명>"
    ]
  }
}
```

- **이 스택의 자리 넷을 채운다** — Flutter 줄을 지우고 나면 git·python 몇 줄만 남는다. 아래 네
  자리가 루틴 작업(커밋·테스트·빌드·설치)의 전부다. **명령을 추측해 적지 말고**, 실제로 물었을 때
  "다시 묻지 않기"로 받은 정답 패턴을 넣는다(§2 판정법). Bash·PowerShell 양쪽 다.
  - **테스트** — 위 블록의 `flutter test` / `--reporter failures-only` 자리
  - **빌드** — `flutter build apk*` 자리
  - **정적 분석**(타입체크·린트·포맷) — `flutter analyze` / `dart format *` 자리
  - **잠금 파일대로 설치** — `flutter pub get` 자리. 패키지 **추가**는 열지 않는다(§1)
- `flutter test *`는 안 연다 — 개별 실행은 훅이 막고, 맨몸과 failures-only면 충분하다.
- `Set-Location`/`cd` 규칙을 넣는 이유: cd 훅이 권장하는 대체 수단인데 자동 허용이 아닌
  환경에서 매번 물었다(9건 실측 `[H14]`). 단독 cd는 파괴적이지 않다.
- `flutter pub *`가 아니라 `get`·`outdated`만 — `pub add`는 패키지 추가(§1 남기는 것).
- `Edit(.claude/**)`류는 넣지 않는다 — 죽은 규칙이다 `[H12]`.
- ⚠️ `additionalDirectories`는 문법만 적었고 **실측 전**(2026-08-22) — 다음 `/approval-audit`에서
